# Проверка Tonino Preview 0.1.2

Дата: 14 ноября 2026 года.

Пользователь сообщил об обрыве после ответа, повторных нажатиях «Ответить»,
ошибке ICE через ретранслятор и появлении отдельного приложения вместо обновления.

## Изменения

- Ответ переводит вызов в accepting до запроса TURN; повторные нажатия игнорируются,
  кнопка недоступна во время подготовки. Запрос TURN ограничен 8 секундами.
- Исходящий/принятый звонок использует microphone foreground service. Уход с экрана
  больше не завершает его; polling продолжается до отбоя. Первое входящее из
  полностью закрытого приложения пока не поддерживается: push не реализован.
- Вызов считается active после подключения PeerConnection (DTLS), а не только ICE.
  Старые setup/disconnect-таймеры отменяются, при разрыве даётся 30 секунд.
- Приоритет TURN/TCP; при неудаче выделения адреса до отправки SDP выполняется
  попытка TURN/UDP. Первый relay-адрес передаётся без ожидания полного сбора ICE;
  остальные кандидаты идут через зашифрованные call_ice. Кандидаты до remote SDP
  буферизуются; callbacks прежнего PeerConnection отбрасываются по поколению.
- Сохраняются пакет com.tonino.secure.preview и постоянный сертификат Preview.
  VersionCode повышен с 101 до 102: профиль и переписка обновляются на месте.
- В настройках добавлено обновление через HTTPS-метаданные и FileProvider.
  Проверяются размер, SHA-256, пакет, более высокий versionCode и совпадение
  сертификата. После скачивания открывается системный установщик; подтверждение
  остаётся в Android. Открытие установщика откладывается до завершения звонка.
- TURN на VPS: user-quota 8 вместо 4 для сетевых интерфейсов/повторных вызовов;
  total-quota остаётся 40. Включён ограниченный Docker-журнал (2 файла по 5 МБ).
  Восстановить причину прежних вызовов по нему нельзя: до изменения журнал пуст.

## Границы проверки

Звонковые Android-тесты используют native x86_64, собранный из того же коммита;
Обновление ARM64 APK проверялось с ARM-преобразованием эмулятора. DEX-файлы,
AndroidManifest.xml и resources.arsc в ARM64 и x86_64 APK совпадают побайтно.
Во всех тестах создаются только временные личности в памяти; производственные
профили и переписка не читаются и не изменяются. HTTP relay с SQLite работает
внутри CI, голосовой TURN — на действующем VPS. TURN credentials краткоживущие;
общие секреты и закрытый ключ подписи не передаются в CI-артефакты.

Физические микрофоны, разговорный динамик, Bluetooth и сети операторов требуют
повторной проверки двумя телефонами. TURN/TLS на 443 пока нет. Независимый аудит
не проводился. Статус installer-диалога при будущих обновлениях зависит от Android:
0.1.1 ещё не содержит кнопки обновления, поэтому переход на 0.1.2 выполняют один
раз открытием скачанного APK; последующие обновления запускаются из настроек.
