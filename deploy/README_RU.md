# Запуск тестового сервера Tonino

Этот комплект предназначен для первого теста двух телефонов. Сервер Tonino уже
развёрнут на существующем VPS в режиме [общего ingress](SHARED_VPS_RU.md):
публичный HTTPS, обмен двух клиентов libsignal, TURN по UDP/TCP и скачивание APK
проверены. Голос на телефонах и прохождение через сети операторов ещё проверяются
вручную. Ниже сохранена инструкция для отдельной установки с доменным именем.

Для небольшой тестовой группы: отдельный VPS, Ubuntu 24.04, 1 ядро / 2 ГиБ RAM,
25 ГиБ диска и публичный IPv4. Это стартовый ориентир, а не результат нагрузочного
испытания. Нужен обычный VPS с root/SSH; общему веб-хостингу этот комплект не подходит.

## Подготовка

1. Направьте DNS-запись A выбранного поддомена на публичный IPv4 VPS. Для теста
   используйте прямой DNS без HTTP-прокси. Не добавляйте AAAA, если IPv6 не настроен.
2. Установите Docker Engine и Compose по официальной инструкции:
   https://docs.docker.com/engine/install/ubuntu/.
3. Скопируйте этот репозиторий на отдельный сервер и откройте его каталог.
4. Создайте конфигурацию, подставив **свои** домен и IP:

```bash
sudo python3 deploy/configure.py chat.example.com 203.0.113.10
```

Пример IP выше — только обозначение места для подстановки; скрипт отвергнет его
как непубличный. Скрипт не перезаписывает существующие секреты или базу.
Каталог `deploy/data` принадлежит UID 1000, под которым работает контейнер relay.
Файл `deploy/.env` содержит закрытый код регистрации `JOIN_CODE` и секрет TURN.
Не коммитьте и не публикуйте эти файлы.

5. Разрешите на firewall VPS и в панели провайдера:

| Назначение | Порты |
|---|---|
| SSH | Используемый вами TCP-порт SSH |
| HTTPS и получение сертификата | 80/TCP, 443/TCP |
| TURN | 3478/TCP, 3478/UDP |
| Голосовой трафик TURN | 49160–49200/UDP |

Не меняйте правила SSH вслепую: сохраните текущий доступ к серверу.
TURN публикуется напрямую на host-сети, поэтому нужны правила не только для Docker.
API-порт 8080 наружу не публикуется.

6. Запустите:

```bash
sudo docker compose -f deploy/compose.yaml --env-file deploy/.env up -d --build
curl --fail https://chat.example.com/healthz
```

Успешная проверка возвращает `{"status":"ok","protocol":1}`. Дождитесь выдачи
сертификата Caddy, прежде чем подключать телефоны. Самоподписанные сертификаты
и отключение проверки TLS клиентом не поддерживаются.

## Подключение двух телефонов

1. Установите тестовый APK на оба Android-устройства (Android 8.0+, ARM64).
2. Введите одинаковый адрес `https://ваш-поддомен`, своё имя и `JOIN_CODE` из
   `deploy/.env`. Код регистрации вводится локально, в приложении.
3. На первом телефоне создайте приглашение и передайте его второму. На втором
   нажмите «Добавить собеседника» и вставьте текст приглашения.
4. Повторите в обратную сторону. Приглашения одноразовые, действуют 24 часа.
   Создание нового приглашения отменяет предыдущее неиспользованное.
5. Откройте чат, нажмите на имя собеседника и сверьте код проверки на обоих
   телефонах по доверенному каналу. Полный код должен совпасть.
6. Отправьте сообщения в обе стороны. «На сервере» означает принятие пакета;
   «Доставлено» появляется только после зашифрованного подтверждения второго
   устройства. Проверьте очередь при отключении сети и после перезапуска.
7. Оставьте приложения открытыми. Разрешите микрофон, позвоните в обе стороны,
   проверьте звук, отключение микрофона, громкую связь и завершение вызова.
8. Повторите звонок, подключив один телефон к Wi-Fi, второй — к мобильной сети.

## Ограничения первой версии

- Входящие звонки и синхронизация работают при открытом приложении. При уходе
  в фон звонок завершается. Push и фоновый сервис ещё не реализованы.
- Восстановления, переноса профиля и нескольких устройств на один профиль нет.
  Удаление приложения приводит к потере локальных ключей и истории.
- Приглашения сейчас добавляются вставкой текста. QR-код отображается, сканера
  внутри приложения нет. Номера телефонов и адресная книга не используются.
- Один сервер для обоих собеседников; групп и вложений нет.
- У профиля 16 одноразовых наборов ключей для начала новых сессий. Автоматическое
  пополнение и ротация подписанного ключа ещё не реализованы. При исчерпании
  сервер отказывает в начале новой сессии; существующие сессии продолжаются.
- Ретрансляция TURN включена принудительно. TLS/TURN на порту 443 пока не
  поддерживается; в сетях, запрещающих 3478, звонок может не установиться.
- TURN выдаёт часовые credentials; для первого теста ограничьте вызовы 30 минутами.
- В сервере установлен лимит 200 профилей и 1000 недоставленных пакетов на
  получателя. Пакеты удаляются логически через 7 дней либо после подтверждения.
- Сервер видит IP, адресатов, время, объём пакетов и факт обращений к TURN.
  Шифрование содержимого не скрывает эти метаданные.
- Наличие libsignal не является аудитом этого приложения. Проверка на двух
  физических телефонах и независимая проверка безопасности ещё необходимы.

База `deploy/data/tonino.sqlite` и её WAL содержат учётные записи, публичные
ключи и зашифрованную очередь, но не ключи расшифровки или историю телефона.
Для смены сервера переноса учётных записей пока нет: не удаляйте работающую базу.

Проверить журналы: `sudo docker compose -f deploy/compose.yaml --env-file deploy/.env logs --tail 50`.
Не включайте подробные журналы HTTP-заголовков или шифрования.
